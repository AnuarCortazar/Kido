🦊 Mascota KIDO — Evolución Ramificada
La edad define el ESTILO · el gusto define la RAMA temática

✅ Decisión: Digitales + bonos al correo del padreDan ~80% del efecto motivacional con ~20% del riesgo. El niño ve "ganaste una salida a [parque]", pero el padre controla, valida y recibe. Sin manejar direcciones físicas de menores ni logística inicial.
⚠️ Por qué se descartaron los premios físicos a domicilioEnviar objetos al hogar implica recolectar dirección física de un menor (información sensible bajo normativa de protección de menores), requiere logística propia que destruye el margen freemium, y dulces/frutas como incentivo de consumo a menores conllevan riesgo reputacional. Reevaluable solo con tracción y capital.
🔐 Consentimiento Parental Verificable
Requisito legal para activar canje de bonos (Fase 2)
📋 Principio legalLa normativa de protección de menores exige que el consentimiento parental sea verificable — no un simple checkbox. El método debe estar "razonablemente diseñado" para asegurar que quien consiente es el adulto responsable.

🪜 Flujo propuesto (doble barrera)

  1. Registro del padre con email verificado. El padre crea la cuenta familiar; se confirma el email con código de un solo uso. El niño nunca registra datos de contacto.
  2. Verificación de adulto vía micro-transacción. Para habilitar canje de bonos, micro-transacción con tarjeta (cargo mínimo reembolsable o autorización $0). Método aceptado: demuestra adulto con medio de pago.
  3. PIN parental de 4–6 dígitos. Configurado por el padre. Requerido en CADA canje. El niño no puede completar ningún canje sin esta barrera.
  4. Notificación y confirmación final por email. Cada solicitud dispara un email al padre que debe confirmar explícitamente antes de procesar el bono.
  5. Registro auditable. Log de cada consentimiento: fecha, qué se autorizó, método e IP. Permite responder a auditorías y solicitudes de revisión/eliminación de los padres.

⚙️ Stack Técnico Definitivo — Arquitectura Híbrida
Supabase (infraestructura) + .NET (lógica de negocio) — velocidad Y robustez
🔑 La clave que resuelve la indecisiónSupabase NO es lo opuesto a .NET. Supabase es PostgreSQL + Auth + Storage + Realtime empaquetados. Se usa como capa de infraestructura (velocidad de desarrollo) mientras .NET maneja la lógica de negocio sensible (fortaleza del equipo). No se sacrifica ninguna.
📱

Frontend — Flutter (Dart)

Motor Impeller, 60–120 FPS, pixel-perfect. Aquí vive TODA la fluidez: animaciones de KIDO, transiciones, respuesta táctil. Esto NO es trabajo de backend.

▼ SDK Supabase (auth/datos) · API REST a .NET (lógica) ▼
⚙️

Lógica de negocio — .NET / C#

Fortaleza del equipo. Motor Sensei (IA), economía KidoCoins, validación de consentimiento parental, facturación multimoneda, reglas anti-fraude.

▼ ▼
🗄️

Infraestructura — Supabase

PostgreSQL gestionado + Auth + Storage + Realtime, listos en minutos. Aquí está la velocidad/compactación de desarrollo que buscabas. Open-source = estrategia de salida, sin lock-in profundo.

◀ Supabase Realtime (caso de uso ideal) ▶
⚡

Realtime — Supabase Realtime

Solo para el ranking semanal (su caso de uso perfecto). Sin escribir código de sockets. El resto de la app es single-player y NO necesita realtime de backend.

🎯 Aclaración conceptual importanteLa fluidez, tiempo de respuesta y "realismo" de animaciones es 100% Flutter en el dispositivo — no toca el servidor. El "Realtime" de backend es sincronización de datos en vivo entre dispositivos, y en esta app eso aplica únicamente al ranking semanal. La app es educativa single-player, no colaborativa.

📊 Decisión de backend — por qué híbrido y no puro

OpciónVeredicto para KidLearn
Supabase + .NET (híbrido)✅ Elegido — velocidad de Supabase para infra + robustez .NET para lógica sensible. Lo mejor de ambos sin sacrificar ninguno
Solo .NET (todo a mano)Robusto pero lento: reconstruir auth, storage, realtime desde cero retrasa el MVP innecesariamente
Solo Supabase (BaaS completo)Rápido pero la lógica sensible (Sensei, economía, consentimiento) queda débil en Edge Functions; desaprovecha skill .NET del equipo
Firebase (BaaS completo)NoSQL inadecuado para economía relacional y datos de menores; lock-in Google Cloud sin self-hosting
💰 Nota de costos honestaEl plan Pro de Supabase ($25/mes) trae la instancia de cómputo más pequeña; para producción real se necesita añadir cómputo. Es predecible, pero presupuéstalo desde ahora para evitar sorpresas.
